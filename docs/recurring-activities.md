# กิจกรรมส่วนตัวแบบเกิดซ้ำ

## วิธีใช้

รัน `php artisan migrate` เพื่อเพิ่มตารางกฎซ้ำและคอลัมน์อ้างอิงในกิจกรรมเดิม จากนั้นเปิด `/activities`

เลือกไม่ซ้ำ ทุกสัปดาห์ หรือทุกเดือน กรอกจำนวนครั้งเมื่อเลือกซ้ำ โดยนับรวมครั้งแรก เช่น 5 ครั้ง = ครั้งแรกกับอีก 4 ครั้ง การแก้ไขและลบมีผลกับทั้งชุด รวมรายการย้อนหลัง แต่ไม่เปลี่ยน snapshot ของรอบที่เก็บไว้แล้ว

ปฏิทินคำนวณเฉพาะสัปดาห์ที่เลือก ส่วนรายการด้านล่างแบ่งกิจกรรมเกิดซ้ำและกิจกรรมครั้งเดียว หน้าของแต่ละกลุ่มแยกกันและไม่จำกัดข้อมูลในปฏิทิน

## กติกา

- เวลาทั้งหมดตีความเป็น Asia/Bangkok ทุก occurrence คงระยะเวลาเดิม รวมกิจกรรมคร่อมเที่ยงคืนและหลายวัน
- รายสัปดาห์ห่างกัน 7 วัน รายเดือนยึดวันที่ต้นฉบับ ถ้าไม่มีวันนั้นใช้วันสุดท้ายของเดือน เช่น 31 ม.ค. → 28/29 ก.พ. → 31 มี.ค.
- จำนวนครั้งอย่างน้อย 2 ไม่มีเพดานทางธุรกิจ แต่ตรวจขอบเขตจำนวนเต็มของฐานข้อมูลถึง 2,147,483,647
- เก็บเพียงต้นฉบับและกฎ ไม่สร้างแถวกิจกรรมสำหรับแต่ละครั้ง และไม่วนขยายครบทั้งชุดเมื่อขอดูเพียงหนึ่งสัปดาห์
- เวลาที่แตะขอบไม่ถือว่าชน (`start < other.end` และ `end > other.start`)
- กิจกรรมส่วนตัวเห็นได้เฉพาะเจ้าของ Snapshot เก็บเฉพาะ start/end ไม่เก็บชื่อ
- เมื่อเก็บ snapshot แล้ว การวิเคราะห์และโหวตใช้ข้อมูลที่ล็อกไว้ เจ้าของห้องต้อง reset รอบจึงนำตารางใหม่มาใช้
- ไม่มีการแก้เฉพาะครั้ง ยกเว้นบางครั้ง หรือการซ้ำทุก N สัปดาห์ในรุ่นนี้

## ทดลองด้วยมือ

1. สร้างกิจกรรม 31 ม.ค. 09:00–10:00 เลือกทุกเดือน 3 ครั้ง
2. เลือกสัปดาห์ที่มี 28 ก.พ. (หรือ 29 ก.พ. ปี leap) และ 31 มี.ค. ตรวจเวลาทั้งสองครั้ง
3. เปิดสัปดาห์ในเดือนเมษายน ต้องไม่พบครั้งที่ 4
4. แก้เป็นรายสัปดาห์หรือไม่ซ้ำ ตรวจว่ารายการและปฏิทินเปลี่ยนตามกัน
5. สร้างรอบที่ครอบคลุม occurrence ที่ไม่ใช่ครั้งแรก เข้าร่วม แล้วเปิดโหวตด้วย `php artisan rounds:advance ID voting` ในเครื่องพัฒนา เวลาที่ไม่ว่างต้องไม่ให้โหวต
6. แก้กิจกรรมส่วนตัวหลังเปิดโหวต ตัวเลือกเดิมต้องไม่เปลี่ยน Reset รอบแล้วค่อยเปิดใหม่จึงใช้ตารางล่าสุด
7. ปิดด้วย `php artisan rounds:advance ID final` ถ้าไม่มีผู้โหวตต้องแสดงข้อความระบบเลือกอัตโนมัติ

## ตรวจสอบอัตโนมัติ

```sh
php artisan test --filter=UserBusySlotRecurrenceTest
php artisan test --filter=RoundVotingTest
php artisan test
php -d memory_limit=512M vendor/bin/phpstan analyse --memory-limit=512M
```

ชุดทดสอบใช้ SQLite ในหน่วยความจำ การผ่านชุดทดสอบนี้ไม่ได้ยืนยัน row locking บน MySQL/PostgreSQL หรือการแสดงผลจริงบนมือถือ ก่อน deploy ต้องตรวจ migration และคำขอพร้อมกันบนฐานข้อมูลชนิดที่ใช้จริงด้วย
