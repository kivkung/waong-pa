# วิเคราะห์เวลาและโหวต (ข้อ 2–4)

## ขั้นตอน

- **Join & Prepare:** ใช้ขั้นตอนรับสมาชิกและตารางส่วนตัวเดิม
- **Review:** หลังปิดรับและครบ `ROUND_SNAPSHOT_DELAY_MINUTES` ระบบเก็บสำเนาเวลาไม่ว่าง แล้วสร้างตัวเลือกจากสำเนาเพียงครั้งเดียว การแก้ตารางส่วนตัวภายหลังไม่เปลี่ยนตัวเลือกในรอบนี้
- **Voting:** เปิดตาม `voting_starts_at` สมาชิกในรอบเห็นเฉพาะตัวเลือกที่ตนว่าง โหวตได้หนึ่งตัวเลือก และเปลี่ยนได้ก่อน `final_starts_at` เซิร์ฟเวอร์ตรวจเวลา สมาชิก และความพร้อมซ้ำทุกครั้ง
- **Final:** ล็อกคะแนน ตั้งรอบเป็น `completed` และเปิดให้สร้างรอบใหม่ แสดงเวลาที่ได้รับเลือกและดาวน์โหลด `.ics` ได้

## วิธีวิเคราะห์และให้คะแนน

สร้างเวลาเริ่มทุก 30 นาที ภายในวันที่และกรอบเวลาที่เจ้าของกำหนด ทุกตัวเลือกต้องยาวครบ `duration_minutes` และจบภายในกรอบเวลาในวันนั้น

สมาชิกว่างเมื่อไม่มีสำเนาช่วงไม่ว่างใดซ้อนกับช่วงนัดทั้งหมด โดยใช้ `busy.start < candidate.end && busy.end > candidate.start` เวลาที่แตะขอบพอดีถือว่าไม่ซ้อน และนับสมาชิกแต่ละคนครั้งเดียวแม้มีหลายกิจกรรม

กรองเงื่อนไขอาจารย์ `all` หรือ `at_least` ก่อนเก็บตัวเลือก ไม่เก็บเวลาที่ไม่มีคนว่าง คะแนนความพร้อมเท่ากับจำนวนคนว่าง ไม่ใช้ค่าน้ำหนักสมาชิก ร้อยละความพร้อมเท่ากับจำนวนคนว่างหารจำนวนสมาชิกในรอบคูณ 100

ตัวเลือกเรียงคะแนนความพร้อมมากไปน้อย หากเท่ากันเรียงเวลาเริ่มเร็วกว่า ขณะโหวตยังคงลำดับนี้หลังกรองเวลาที่ชนตารางของผู้ใช้

ผลสุดท้ายใช้จำนวนโหวตสูงสุด หากเท่ากันเลือกคะแนนความพร้อมสูงกว่า แล้วเลือกเวลาเร็วกว่า หากไม่มีโหวตหรือไม่มีตัวเลือก จะจบรอบโดยไม่มีผู้ชนะ พร้อมข้อความอธิบาย

## การติดตั้งและใช้งาน

```sh
php artisan migrate
php artisan schedule:work
```

ใช้ scheduler เดิม `rounds:process` ทุกนาทีได้ และหน้าแสดงรอบจะตรวจขั้นตอนตามเวลาเมื่อเปิดหน้า ให้รีเฟรชหน้าเมื่อถึงเวลาเปลี่ยนขั้นตอน

หน้า Review, Voting และ Final อยู่ในหน้ารายละเอียดรอบเดิม `/rooms/{room}/rounds/{round}` เฉพาะสมาชิกห้องเห็นตัวเลือกและผลโหวต การดาวน์โหลดปฏิทินใช้เขตเวลาของแอปเช่นเดียวกับตารางเดิม แล้วส่งออกเวลา UTC ในไฟล์ `.ics`

การรีเซ็ตรอบในช่วงที่ยัง active จะล้างสำเนา ตัวเลือก และโหวตทั้งหมด พร้อมเก็บสมาชิกเดิมไว้ การยกเลิกรอบปิดการโหวตทันที

## ตรวจสอบ

### ทดลองผ่านเว็บโดยไม่ต้องรอเวลา

คำสั่งต่อไปนี้แก้เวลาในฐานข้อมูลของรอบที่ระบุจริง ใช้กับรอบทดสอบในเครื่องพัฒนา (`APP_ENV=local`) เท่านั้น ไม่ได้เปลี่ยนเวลาของคอมพิวเตอร์

1. สร้างรอบ เข้าร่วมรอบ และบันทึกตารางไม่ว่างของสมาชิกให้เสร็จก่อน
2. ดู ID ของรอบจาก URL เช่น `/rooms/2/rounds/5` หมายถึงรอบ ID `5` (ไม่ใช่เลขรอบที่แสดงในชื่อ)
3. เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วเปิดโหวตทันที:

```sh
php artisan rounds:advance 5 voting
```

คำสั่งนี้ปิดรับสมาชิก ข้ามเวลารอเก็บสำเนา วิเคราะห์เวลา และเปิดโหวตให้ 1 ชั่วโมง จากนั้นรีเฟรชหน้ารายละเอียดรอบ ถ้ามีสำเนาอยู่แล้วจะใช้สำเนาเดิม

4. ลองเข้าสู่ระบบด้วยสมาชิกแต่ละคน ตรวจว่าไม่เห็นเวลาที่ชนตารางของตน และลองโหวตหรือเปลี่ยนตัวเลือก
5. เมื่ออยากดูผลทันที ให้ปิดโหวต:

```sh
php artisan rounds:advance 5 final
```

รีเฟรชหน้าเพื่อดูผู้ชนะ คำสั่งนี้สรุปจากโหวตที่มีอยู่ ถ้ายังไม่มีใครโหวตจะไม่มีผู้ชนะ หลังจบรอบจะโหวตเพิ่มไม่ได้ ถ้าจะทดลองใหม่ให้สร้างรอบใหม่ ส่วนคำสั่ง `rounds:process` ปกติเพียงตรวจเวลาปัจจุบัน ไม่ได้ข้ามเวลาให้

### ทดสอบอัตโนมัติ

```sh
php artisan test --filter=RoundVotingTest
```

ครอบคลุมการซ้อนของเวลา คะแนนและลำดับ เงื่อนไขอาจารย์ สำเนาที่ไม่เปลี่ยนตามตารางจริง สิทธิ์โหวต การเปลี่ยนโหวต ขอบเขตเวลาปิด คะแนนเท่ากัน ไม่มีผู้โหวต ไม่มีตัวเลือก ปฏิทิน การรีเซ็ต และยกเลิก

ชุดทดสอบใช้ฐานข้อมูล SQLite ในหน่วยความจำและจำลองเวลา จึงไม่ต้องรอเวลาจริง และไม่ใช้ข้อมูลโหวตในฐานข้อมูลที่เปิดผ่านเว็บ

## อ่านโค้ดสำหรับมือใหม่

- `app/Actions/GenerateRoundCandidates.php`: ใช้ `for` ลองเวลาเริ่มทีละ 30 นาที ใช้ `foreach` ตรวจสมาชิกและช่วงไม่ว่าง ใช้ `if` ตรวจเวลาชนกัน และ `break` หยุดตรวจเมื่อพบว่าชน จากนั้นนับคนว่างด้วย `count()`
- `app/Http/Controllers/RoundController.php`: โหลดตัวเลือกและเรียงด้วย `orderByDesc('available_count')` คือจำนวนคนว่างมากขึ้นก่อน แล้ว `orderBy('start_at')` คือเวลาเร็วขึ้นก่อน
- `app/Http/Controllers/RoundVotingController.php`: ตรวจสิทธิ์และเวลาว่าง หาคะแนนเดิม ถ้าไม่มีใช้ `new RoundVote` แล้วบันทึกด้วย `save()`
- `app/Actions/ProcessMeetingRound.php`: ทำงาน 3 ขั้น คือปิดรับสมาชิก เก็บสำเนา และเปิดโหวตหรือสรุปผล
- `routes/console.php`: ลงทะเบียนคำสั่ง Terminal สำหรับประมวลผลตามเวลาปกติและข้ามเวลาทดสอบ

ยังใช้ `DB::transaction` และ `lockForUpdate` เพื่อกันข้อมูลผิดพลาดเมื่อมีหลายคำขอเข้ามาพร้อมกัน ทั้งสองเป็นเครื่องมือของ Laravel ส่วน `function (...) use (...)` คือฟังก์ชันย่อยที่นำตัวแปรจากภายนอกเข้าไปใช้งาน
