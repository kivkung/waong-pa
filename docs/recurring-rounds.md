# สร้างรอบใหม่อัตโนมัติ

## แนวทางและเหตุผล

เหมาะกับห้องที่ต้องนัดกันเป็นประจำ แต่ตารางของสมาชิกเปลี่ยนไปในแต่ละครั้ง ระบบสร้างรอบใหม่เพื่อให้เข้าร่วม เก็บ snapshot วิเคราะห์ และโหวตใหม่ โดยไม่คัดลอกสมาชิก โหวต หรือตารางที่ล็อกไว้ของรอบเก่า

แต่ละห้องยังมีรอบ active ได้เพียงหนึ่งรอบ จึงไม่สร้างรอบถัดไปซ้อนกับรอบเดิม ต้องกำหนดเวลาให้รอบเดิมสรุปผลก่อนรอบถัดไปเปิดรับสมาชิก รุ่นนี้ตั้งได้ 2–52 รอบตามแผน (รวมรอบแรก) เพื่อให้ตรวจสอบกำหนดการทั้งชุดได้ก่อนบันทึก

## วิธีใช้

1. ในฟอร์มสร้างรอบ เลือก “สร้างรอบใหม่อัตโนมัติ” เป็นทุกสัปดาห์หรือทุกเดือน
2. ระบุจำนวนรอบรวมรอบแรก เช่น 4 รอบ = รอบแรกและรอบอัตโนมัติอีก 3 รอบ
3. กรอกกรอบค้นหาและเวลา Join → Review → Voting → Final ของรอบแรกตามเดิม
4. ในแต่ละรอบ สมาชิกต้องเข้าร่วมใหม่หรือเจ้าของห้องเลือกสมาชิกใหม่ แล้วโหวตใหม่ตามกำหนดการ
5. หน้ารายละเอียดรอบแสดงเวลาเปิดรับรอบถัดไปและจำนวนรอบที่ข้าม เจ้าของห้องกด “หยุดสร้างรอบถัดไป” ได้ แม้รอบปัจจุบันจบแล้ว การหยุดไม่ยกเลิกรอบที่สร้างไปแล้ว

การยกเลิกรอบหรือ reset รอบที่ผูกกับแผนจะหยุดแผนนั้นด้วย การ reset ไม่เปลี่ยนเวลาในต้นฉบับของแผนเดิม และจะไม่เริ่มแผนใหม่เอง

## การเลื่อนวัน

วันอ้างอิงคือ `join_starts_at` ของรอบแรก:

- รายสัปดาห์: บวก 7 วันต่อครั้ง
- รายเดือน: เลื่อนไปแต่ละเดือนจากวันต้นฉบับ หากไม่มีวันนั้นใช้วันสุดท้ายของเดือน เช่น 31 ม.ค. → 28/29 ก.พ. → 31 มี.ค.
- คำนวณจำนวนวันที่ต่างจากวันเปิดรับต้นฉบับ แล้วเลื่อนทุกเฟสและวันที่ค้นหาด้วยจำนวนวันเดียวกัน ทำให้ระยะห่างของแต่ละเฟสและความยาวกรอบค้นหาไม่เปลี่ยน
- เช่น เปิดรับ 31 ม.ค. และค้นหานัด 1–3 ก.พ. รอบถัดไปเปิดรับ 28 ก.พ. และค้นหา 1–3 มี.ค. รอบถัดไปอีกเปิดรับ 31 มี.ค. และค้นหา 1–3 เม.ย.
- เวลาในแต่ละวัน ระยะเวลานัด และกฎอาจารย์ใช้ค่าเดิม เขตเวลาคือ Asia/Bangkok

## อะไรทำให้สร้างรอบ

`php artisan rounds:process` ตรวจรอบปัจจุบันก่อน แล้วตรวจแผนที่ถึงเวลาเปิดรับรอบถัดไป คำสั่งเดิมถูกเรียกทุกนาทีจาก Laravel Scheduler

เครื่องพัฒนาต้องเปิดเซิร์ฟเวอร์ Laravel และรัน `php artisan schedule:work` ส่วนเซิร์ฟเวอร์จริงต้องตั้งให้ Laravel Scheduler ทำงานตามปกติ ผู้ใช้เว็บไม่ต้องเปิด Terminal เอง การเปิดหน้ารอบอย่างเดียวเปลี่ยนเฟสของรอบได้ แต่ไม่เรียกสร้างรอบอัตโนมัติในรุ่นนี้

หากห้องมีรอบ active อื่น ระบบจะรอ หากรอจนถึงเวลาปิดรับสมาชิกของรอบตามแผน จะข้ามรอบนั้น เช่นเดียวกับกรณีหยุดเครื่องไว้นาน ไม่สร้างรอบย้อนหลังที่ไม่มีโอกาสเข้าร่วม จำนวนรอบที่ข้ามนับรวมจำนวนตามแผน และแสดงในหน้ารายละเอียด

## การตรวจสอบ

```sh
php artisan migrate
php artisan test --filter=RoundRecurrenceTest
```

ชุดทดสอบจำลองเวลา จึงตรวจรอบถัดไปได้โดยไม่ต้องรอจริง ครอบคลุมรายเดือน/สิ้นเดือน, การสร้างเมื่อถึงเวลา, การเรียกซ้ำ, ห้องที่มีรอบ active, การข้ามรอบที่พลาด, สิทธิ์เจ้าของ, การหยุด/ยกเลิก/reset, การแยกข้อมูลระหว่างรอบ และ migration ไป-กลับบน SQLite

แผนและการสร้างรอบอยู่ใน transaction พร้อมล็อกแผนและห้อง มี unique index ของแผน/ลำดับรอบ และ active marker ของห้องเป็นตัวกันซ้ำ ชุดทดสอบ SQLite ไม่ยืนยันการล็อกพร้อมกันจริงบน MySQL/PostgreSQL ต้องตรวจบนฐานข้อมูลที่จะใช้ก่อน deploy
